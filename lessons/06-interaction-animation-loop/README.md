# 第 6 课：交互、动画与渲染循环

WebGL 应用不是一次性绘制图片，而是持续处理输入、更新时间状态、再把状态渲染成画面。本课建立最小但可扩展的 `input -> state -> update -> render` 闭环：事件监听只修改状态，`requestAnimationFrame` 统一驱动动画和绘制。

## 学习目标

- 理解 `requestAnimationFrame` 与浏览器刷新节奏的关系。
- 使用 `deltaTime` 做帧率无关的状态更新。
- 把鼠标/触摸/键盘输入转换为渲染状态，而不是在事件回调里直接绘制。
- 学会在循环外创建 WebGL 资源，避免每帧重复分配。

## 核心概念

### 1. 输入只改状态

事件回调适合记录“用户想做什么”：拖拽方向、是否暂停、目标位置等。真正的 WebGL draw call 放在渲染循环里，避免输入事件和绘制顺序耦合。

### 2. 动画使用时间而不是帧数

不同设备刷新率可能是 60Hz、120Hz 或更高。如果用“每帧加固定值”，动画速度会随刷新率变化。本课用 `deltaTime` 更新角速度和惯性。

### 3. 状态更新与绘制职责分离

`update(dt)` 只处理状态演进，`render()` 只把状态画出来。这个边界是后续接入物理、UI、调试面板或多 pass 渲染的基础。

## 运行方式

在仓库根目录启动静态服务：

```bash
python3 -m http.server 8080
```

打开：

```text
http://localhost:8080/lessons/06-interaction-animation-loop/
```

## 你应该看到

- 一个三角形/指针组合持续旋转并带有拖拽惯性。
- 鼠标或触摸拖动画布会改变旋转方向和速度。
- 按空格可以暂停/继续动画，点击“重置”按钮恢复初始状态。

## 架构提示

把 WebGL 资源初始化、输入系统、状态更新和渲染函数拆开。大型应用中可以进一步演进为 `InputSystem -> SimulationSystem -> RenderSystem`，但最小 demo 也应该保持这个边界。

## 延伸练习

1. 增加速度滑块，让用户调节自动旋转速度。
2. 添加阻尼开关，对比有/无惯性的交互体验。
3. 将当前状态显示为 JSON，模拟调试面板。
