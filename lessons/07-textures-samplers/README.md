# 第 7 课：纹理与采样器

纹理可以理解为 GPU 上可被 shader 查询的数据表。它不一定来自图片，也可以来自程序生成、视频帧、Canvas、FBO 或数据纹理。本课先用程序生成的棋盘格纹理建立最小闭环，再观察 UV、过滤方式和包裹方式如何改变最终画面。

## 学习目标

- 理解 `texture` 是 GPU 资源，`sampler2D` 是 shader 访问纹理的入口。
- 掌握 `gl.texImage2D` 上传像素数据的基本流程。
- 区分 UV 坐标、纹理单元、采样器 uniform、过滤参数和包裹参数。
- 观察 `NEAREST` 与 `LINEAR` 在放大纹理时的差异。

## 核心概念

### 1. 纹理对象保存数据和采样状态

WebGL 的纹理对象既保存像素数据，也保存 `TEXTURE_MIN_FILTER`、`TEXTURE_MAG_FILTER`、`TEXTURE_WRAP_S/T` 等采样规则。大型项目中通常会把“图片内容”和“采样策略”拆成资源层配置。

### 2. 纹理单元是绑定槽位

片元着色器里的 `sampler2D u_texture` 不是直接指向某个纹理对象，而是指向一个纹理单元编号。本课把棋盘格绑定到 `TEXTURE0`，再执行 `gl.uniform1i(u_texture, 0)`。

### 3. UV 是几何和图像之间的合同

顶点缓冲里的 UV 决定了矩形上每个片元从纹理的哪个位置采样。修改 UV 缩放/偏移会让贴图重复、移动或裁剪。

## 你应该看到

- 一个倾斜矩形显示程序生成的彩色棋盘格。
- 面板可以切换最近邻/线性过滤、重复/边缘夹取。
- 调整 UV 缩放后，纹理重复次数会变化。

## 架构提示

把纹理资源生命周期与业务状态分离：上传、参数设置、销毁属于资源管理；UV、采样器 uniform 和材质参数属于渲染状态。这样后续接入图片加载器或资源缓存时不会污染绘制代码。

## 延伸练习

1. 把棋盘格改成渐变或噪声纹理。
2. 新增第二张纹理，在 fragment shader 中混合两张贴图。
3. 尝试使用非 2 的幂尺寸纹理，并解释为什么包裹/过滤规则会受限制。
